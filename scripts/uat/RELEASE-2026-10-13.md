# Release runbook: changes since Friday 9 October 2026

This runbook covers `22be2e1538` → the head of `main`: the trace, UNK, POD and AON portal work, then the JRNY courier updates and the MS Graph Mail piece. Use it for each environment: UAT (`devflw.jrny.co.za`) first, then the customer site. The general server commands come from `DEPLOY-RUNBOOK.md` in this folder.

**This release breaks existing flows.** Every JRNY, Nucleus and Shoprite step changes the shape of what it returns. Flows that use those pieces must be exported, migrated and re-imported in the same sitting as the deploy (sections 2 and 5).

## 1. What's in the release

| Change | Effect on a running environment | Action needed |
| --- | --- | --- |
| **Piece call trace.** jrny, nucleus and shoprite go to 0.1.0. | Every step now returns `{ ok, sent, output }`, with the old fields under `output`. `{{step_3.waybillNo}}` becomes `{{step_3.output.waybillNo}}`. | Migrate flows (sections 2 and 5). |
| **"If the call fails" setting** on every JRNY, Nucleus and Shoprite action. | The default, "Stop the flow", behaves as before. Failed steps now also show the calls they sent, with secrets redacted. | Optional: add failure branches (section 6). |
| **Find Hub Code falls back to `UNK`.** | An address that matches no hub, or several, now books with hub code `UNK` instead of failing the run. A failed call to Nucleus still fails. | None. To keep the old behaviour, set "If no hub code is found" to "Fail". |
| **Get PODs Extra (Bulk) returns clean records.** | The output is now `{ waybills: [{ waybillNumber, delivered, podSignedBy, podSignedAt, manifestDate, noParcels, grvNumber, trackingUrl, podUrl }], notFound }` instead of Nucleus's raw `ResultSets`. Long lists are sent 50 at a time. | Fix any flow that reads `output.ResultSets` from this step by hand. The migration tool doesn't do it. |
| **Nucleus connection: Tracking URL and POD URL** (optional). | Without them, `trackingUrl` and `podUrl` are `null`. Create Waybill Import Header now also returns `trackingUrl`. | Add the URLs once Nucleus provides them (section 7). |
| **New piece: AON Customer Portal** (`@jrnyflw/aon-portal`). | Nothing until it's enabled. | Add `aon-portal` to `AP_DEV_PIECES` (section 4). |
| **JRNY piece: errors a Router can read.** | With "Continue", a failed JRNY step now also returns `error.code` (e.g. `VALIDATION_ERROR`), `error.codes` (every code, including per-line ones such as `STOCK_ITEM_NOT_FOUND` and `ADDRESS_NOT_FOUND`) and `error.details`. Generated JRNY actions now describe JRNY errors like the curated ones. | Optional: switch "message contains" Router conditions to `error.codes` (List) contains. |
| **JRNY piece: Courier Response fields.** | Adds the Manifested status and Status At, Hub Code, Courier Warning, POD URL, GRN Number and Failed Step. Error Message is now stored by JRNY. | Optional: send Hub Code and Courier Warning from the booking flow (section 6). |
| **JRNY piece: List Courier Dispatches** and the refreshed API (dispatch notes gain courier filters). | New action; nothing changes until a flow uses it. | None. |
| **New piece: MS Graph Mail** (`@jrnyflw/ms-graph-mail`). | Nothing until it's enabled and connected. | Add `ms-graph-mail` to `AP_DEV_PIECES` (section 4). The M365 admin creates the app registration (section 7). |
| **Engine log redaction fix** (`@activepieces/shared` 0.72.2). | A failed HTTP call in any piece no longer writes its request body to the container logs. Before, that included the Nucleus password and would have included the MS Graph client secret. | None. Logs from before the deploy may contain the Nucleus password: consider changing it, and clear old logs if they're kept. |
| **`@jrnyflw/piece-trace`**, a shared library. | Built into the image automatically. | Nothing. **Do not** add it to `AP_DEV_PIECES`; it isn't a piece. |

## 2. Before the deploy (workstation)

1. **Push `main`.** The servers pull from `origin`.
   ```bash
   cd ~/repo/jrnyflw && git checkout main && git log --oneline -1   # 423528278d or later
   CLAUDE_PUSH=yes git push origin main
   ```
2. **Decide whether JRNY is ready.** Section 6 adds failure branches that send JRNY a Courier Response with status `failed` while the dispatch is still `awaiting_booking`. Until JRNY accepts that (see `docs/integrations/jrny/hub-code-failures.md`), JRNY rejects the call and the run fails anyway. Nothing is hidden, but JRNY shows nothing either.
   - **If JRNY isn't ready:** deploy, migrate and leave the routers out (skip section 6). The flows then behave exactly as they did before, apart from the new outputs and the UNK fallback.
3. **Export every flow that uses jrny, nucleus or shoprite** from the environment you're about to deploy (flow menu → Export). On the customer site that's at least the courier flow. On UAT, include the demo and test flows. Keep these files: they are your rollback copies.
4. **Migrate each export:**
   ```bash
   npx tsx packages/pieces/custom/trace/tools/migrate-flow-cli.ts courier-flow.json courier-flow.migrated.json
   ```
   - Check the printed list of steps migrated and left alone, and the reference count.
   - Skim the diff between the two files.
   - Search the migrated file for `Get PODs Extra` or `get_pod_bulk_extra`. If any later step reads its `ResultSets`, rewrite that reference to the new fields by hand.
5. **Have these ready:**
   - the Shoprite portal API key, if you're adding the portal connection now;
   - the Nucleus Tracking and POD URLs, if Nucleus has sent them.

## 4. Deploy (server, at a quiet time)

The time between step 4 here and the publish in section 5 is when the live flows are broken. Keep it short.

```bash
cd ~/repo/jrnyflw
git pull --ff-only && git log --oneline -1                 # must show the merge of jrny-courier-sync or later

grep '^AP_DEV_PIECES' .env.uat                              # note the current list
```

Edit `.env.uat` and add `aon-portal` and `ms-graph-mail` to the comma-separated `AP_DEV_PIECES` list. Use the folder name exactly, and keep any quotes the line already has. Then:

```bash
grep '^AP_DEV_PIECES' .env.uat                              # confirm aon-portal and ms-graph-mail are there, piece-trace is not
DOCKER_BUILDKIT=1 docker build -f Dockerfile.uat -t jrnyflw-uat:latest .
docker compose --env-file .env.uat -f docker-compose.uat.yml up -d
curl -fsS http://127.0.0.1:${PORT:-3020}/api/v1/flags >/dev/null && echo READY
docker exec jrnyflw-uat-app ls packages/pieces/custom/aon-portal/dist/package.json packages/pieces/custom/ms-graph-mail/dist/package.json
```

## 5. Restore the flows straight away (builder)

1. For each exported flow: open it, import the `.migrated.json` file (flow menu → Import), then **publish**.
2. Runs → retry with "From failed step" any run that failed between the deploy and the publish.
3. In the draft, click **Test step** on each JRNY and Nucleus step so the data selector shows the new shape. Fix any reference the migration couldn't catch, then publish again if anything changed.

## 6. Courier flow: failure handling and the hub code

After each Nucleus step (Find Hub Code, Create Waybill Import Header, Create Waybill Import Dims and Detail):

1. Set **If the call fails** to **Continue and return the error**.
2. Add a **Router** with a branch where `{{step_N.ok}}` is false.
3. In that branch:
   - add JRNY **Courier Response** with Courier Status = Failed and Error Message = `<Step name>: {{step_N.error.message}}`;
   - then add a **Code** step that throws the same message, so the run still shows as failed.
4. Publish.

Steps 1–4 send JRNY a `failed` response while the dispatch is still `awaiting_booking`. Do them once JRNY confirms it accepts that (section 10).

Find Hub Code now uses UNK by default, so its failure branch only catches Nucleus or login problems.

**Hub code and UNK warning on the booking** (JRNY now has both fields, so this needs no Router and can go in straight away). In the booked Courier Response, with `step_N` being **your delivery-address Find Hub Code step**:
- **Hub Code:** `{{step_N.output.hubCode}}`
- **Courier Warning:** `{{step_N.output.matchedOn === 'fallback' ? step_N.output.reason : ''}}`

A blank warning is left out, and a later booking without one clears it. After typing the Courier Warning expression, click **Test step** and check that `sent` shows `courierWarning` only for a UNK booking. The builder must keep the expression as text, not turn it into a broken data chip.

## 7. Connections (builder → Connections)

- **Nucleus:** once Nucleus sends the Tracking and POD URLs, reconnect the Nucleus connection and fill in **Tracking URL** and **POD URL**. Use the exact text Nucleus gives; the waybill number is added to the end. You'll need to re-enter the password.
- **MS Graph Mail:** once the M365 admin has created the app registration, create a connection. The registration needs:
  - the Microsoft Graph **Mail.Send** application permission, with admin consent;
  - an **application access policy limiting it to the sending mailbox**. Without that, the secret can send as anyone in the tenant.

  The connection takes:
  - Tenant ID, Client ID and Client Secret (the secret's value);
  - Sender Mailbox, e.g. the notifications address.

  Saving it checks the credentials with Microsoft. Send yourself a test email from a scratch flow: that's the check of the permission and the mailbox.
- **AON Customer Portal (Shoprite):** create a connection with:
  - Portal URL `https://shoprite.accessoffice.co.za`;
  - the API key from the portal team.

  Saving it checks the key and the URL against the portal.

## 8. Acceptance checks

1. All of these appear in a new flow's piece list: **jrny, nucleus, shoprite, mapper, excel, data-mapper, AON Customer Portal, MS Graph Mail**. JRNY lists **List Courier Dispatches**.
2. The courier flow is published, and its next real run shows each JRNY and Nucleus step with `ok: true`, `sent` and `output`. The `sent` entries show `Authorization: [redacted]`, and the Nucleus login body shows `password=[redacted]`.
3. **Nucleus Get PODs Extra (Bulk), as a Test step in a scratch flow:** use `AON-50330044, SHP-50330075, JRNYNOTREAL0001`. Expect:
   - AON-50330044 with `delivered: true`;
   - SHP-50330075 with `delivered: false`;
   - `JRNYNOTREAL0001` in `notFound`.
4. **AON Customer Portal → List Orders, as a Test step in a scratch flow, status `processing`:** expect the current portal orders. The `sent` entry shows `X-API-Key: [redacted]`.
   - **Do not test Acknowledge Order on the live portal.** It changes real customer orders.

## 9. Rollback

If the courier flow can't be made to work and you have to go back:

```bash
cd ~/repo/jrnyflw
docker tag jrnyflw-uat:pre-2026-10-13 jrnyflw-uat:latest
docker compose --env-file .env.uat -f docker-compose.uat.yml up -d
```

Then, in the builder, import each **original** (unmigrated) export and publish it.

- No database migrations ship in this release, so the database backup is only needed if flows or connections were damaged.
- Leaving `aon-portal` in `AP_DEV_PIECES` on the old image makes the server try to load a folder that doesn't exist. Remove it from `.env.uat` before the `up -d` if the piece list fails to load.
- To rebuild the old code instead of retagging: `git checkout 22be2e1538` and run the build. Return to `main` afterwards.
